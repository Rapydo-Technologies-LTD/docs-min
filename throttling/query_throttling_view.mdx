### Query Throttling via Scout Rules

Query throttling in Rapydo is configured and managed through **Scout Rules** in the Automation section. There is no separate Throttling page — throttling behavior is defined by Scout Rules that combine a **Query Pattern** trigger with a **Rate Limit** action.

## Setting Up a Throttling Rule

Navigate to **Automation → Scout Rules** and create a new rule:

**Rule Definition Fields:**

- **Rule Name** — A descriptive name for the rule (e.g., `Throttle_sql_calc_found_rows`)
- **Trigger: Query Pattern** — The SQL pattern to match. The rule fires when a query contains this text (e.g., `sql_calc_found_rows`)
- **Action: Rate Limit** — The maximum number of matching queries allowed to run concurrently. Additional queries beyond this limit are queued

For full details on trigger and action options, see [Scout Triggers & Actions](/automation/scout_triggers_and_actions).

## Monitoring Throttled Queries

Once a Scout Rule with Rate Limit is active:

- The **Query Throttling** widget on the Dashboard shows the current count of throttled (queued) queries in real time
- Clicking the widget shows the queries currently waiting in the throttle queue, including:
  - **SQL Query** — The full text of the queued query
  - **IP Address** — The source IP of the connection
  - **Username** — The database user who submitted the query
  - **Queue Position** — Where the query sits in the execution queue
  - **Enqueued Time** — When the query entered the queue

## Viewing Rule Activity

In **Automation → Scout Rules**, each rule row shows:

- **Event Count** — How many times the rule has been triggered (throttle applied) since it was created
- **Last Run** — The most recent time the rule matched a query

This gives a clear picture of how frequently the rule is being applied and whether the throttle threshold is well-calibrated for your workload.
