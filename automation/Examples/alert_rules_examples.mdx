#### Alert Rules List

Alert Rules are listed in a table showing the rule name, status, trigger metrics with thresholds, and notification method. Each rule can be enabled or disabled independently without deleting it.

#### Alert Waits and Connection Count

Alert when lock waits and connection count are both elevated simultaneously:

```
Trigger 1: Waits Count > 20
AND
Trigger 2: Connections Count > 150

Samples to Trigger: 3
Notification: Email
Recipients: dba-team@company.com
Notification Interval: 5 minutes
```

Result: Alert fires only when both high lock waits and high connection counts occur at the same time, indicating genuine contention rather than a transient spike.

#### Alert Read and Write IOPS

Alert when storage I/O activity exceeds expected thresholds:

```
Trigger 1: Read IOPS > 5000
AND
Trigger 2: Write IOPS > 3000

Samples to Trigger: 4
Notification: Webhook
Webhook Destination: #database-ops
Notification Interval: 10 minutes
```

Result: Fires when both read and write I/O are simultaneously elevated, which typically indicates a batch job, bulk load, or storage performance bottleneck.

#### Alert Max Query Duration

Alert when a long-running query is detected:

```
Trigger 1: Max Query Duration > 60 seconds

Samples to Trigger: 2
Notification: Email
Recipients: dba-team@company.com
Notification Interval: 5 minutes
```

Result: Fires after two consecutive checks detect a query running longer than 60 seconds. Useful as an early warning before Scout Rules take automated action.

#### Alert Memory and Hosts

Alert when memory is low and many client hosts are connected:

```
Trigger 1: Free Memory < 2048 MB
AND
Trigger 2: Hosts Count > 50

Samples to Trigger: 3
Notification: Webhook
Webhook Destination: #critical-alerts
Notification Interval: 5 minutes
```

Result: Fires when low available memory coincides with a high number of connected client hosts, suggesting memory pressure from concurrent connections.

#### Alert CPU Utilization

Alert when CPU remains elevated for a sustained period:

```
Trigger 1: CPU Utilization > 80%

Samples to Trigger: 5
Notification: Webhook
Webhook Destination: #database-ops
Notification Interval: 3 minutes
```

Result: Fires after 5 consecutive checks show CPU above 80%, confirming a sustained issue rather than a brief spike. Repeats every 3 minutes while the condition persists.
